Design decisions in this build ① 4 states, but only 2 kinds of action → group by action, not one flat list. The page carries Draft, Expiring-soon, Posted-awaiting-link, and Expired. But "Expiring soon" is just an urgent Draft and "Expired" is a dead Draft — those three are one action (post it). "Posted · add link" is a different action (backfill the URL) with no deadline. So the page is three sections by task: Drafts to post → Posted · add link → Expired.
② Sort only inside "Drafts to post". A single time-left sort can't span the whole page — Posted-awaiting-link has no deadline. So only drafts sort by time left (expiring first, countdown chip as lead metadata); the other sections sort by recency.
③ One colour axis, no invented amber. Countdown chips are neutral grey; ≤24h uses dark+bold text (not a new hue) + top position + banner. Red is reserved for Expired (terminal). "Link needed" uses the purple Engage-identity token — it's a neutral to-do, not urgent, so no red, no countdown.
④ Awaiting review = "needs your hand," incl. posted-awaiting-link. It's already posted but tracking is broken until you paste the URL, so the action isn't done — it stays here, not in Sent. Inline paste-field, not a modal.
⑤ Stats mirror the 4 states (Drafts to post · Expiring ≤24h · Posted·add link · Expired) — workload & urgency only. No impressions/likes; those are Sent's job.
⑥ Accessibility. All text ≥ 4.5:1 (incl. the previously-failing draft chip). Page-wide :focus-visible, banner is an aria-live status, pager arrows labelled + 32px+ targets, decorative glyphs aria-hidden, real ul/li semantics, the paste field has a label.
